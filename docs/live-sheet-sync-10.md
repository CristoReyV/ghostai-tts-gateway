# Live sheet sync 10

The app already reads the configured spreadsheet server-side through Google's read-only CSV export. `<GHOSTAI_BILLING_SHEET_ID>` selects the fixed source; the client cannot supply another spreadsheet or raw rows. No Google OAuth, service account, frontend credentials, new dependencies or sharing changes are required for the currently accessible source. A private source would require an authorized server-side reader rather than assuming Codex connector access.

`POST /api/admin/billing` with `action: "sync-preview"` reads current rows, members and commercial records. It returns classified rows, separate currency totals and a state fingerprint, and records `sheet_sync_previewed` under the authenticated OWNER. Preview does not mutate membership or financial data. `action: "sync"` requires that fingerprint and re-reads the source before applying. OPERATOR gets 403 for both actions; `GET ?sync=status` exposes last-sync information to OWNER/OPERATOR.

Email matching is trimmed and case insensitive. New valid members go through `createMemberWithAccess`, retaining the existing hashing, encrypted delivery and activation lifecycle. No secrets are returned. Pending plan changes use a database guard on status, old plan and null activation/expiration. Other plan changes, unsupported plans, duplicates and malformed rows are explicitly reviewed. Missing amounts remain NULL. Members absent from the source remain intact and are marked in the UI.

An OWNER-confirmed sync applies current sheet commercial amounts, including differences from manually edited current prices shown in the preview. The financial RPC checks expected revisions atomically. Historical ledger entries and confirmed payments remain intact. The dashboard separates the current registered commercial total from dated confirmed income; amounts in different currencies are never combined.

A private service-only expiring lease serializes sheet syncs across serverless instances. Official membership creation spans existing service operations; an interrupted run may finish some members before an error. The UI re-fetches state after errors, and the next preview reconciles completed work before retrying. Existing members/keys are never recreated or rotated. The lease expires after 120 seconds if a function is interrupted. Normal release occurs in `finally`.

Successful sync persists source fingerprint, processed-row count, OWNER identity, review rows, absent-member IDs and last-sync time in the existing sync metadata, then records `sheet_sync_applied`. Raw spreadsheet contents, Google credentials, keys and activation tokens are excluded. Both Members and Billing use the same control and engine and re-fetch members, operational counters and financial data without a hard reload. No email sending occurs.
